## 开源前安全初审（2026-11-03，源码审查）

本批基于 `release` 的 `3ad3dba`，仅审查及记录，不修改产品实现、提交、推送、改变仓库可见性或部署。结论：已有认证与授权基础，但尚不满足“安全问题已处理、可直接公开发布”的结论。未跟踪的 `android/` 保留，不在本批源码审查与发布扫描范围内。

0.4.2 的触发机制：启动参数指定 `default_permissions="agentdeck"` 及继承 `:workspace` 的权限配置，但 Windows 未显式覆盖用户配置中的旧 `sandbox_mode`；校验要求该字段为 null，同时核对默认权限和继承关系，任一不符均返回上述通用错误。已知用户配置中的 `danger-full-access` 与这一要求不符；在 0.4.2 Windows 改成 `workspace-write` 仍不满足 null 条件。旧版临时处理为备份并注释冲突项，在核对任务并保存工作后重启电脑，使独立共享运行时重新加载配置；仅重启 Host 会保留共享运行时。操作与恢复条件见[使用与维护](usage.md#windows-权限配置冲突)，尚未取得该用户修改后的恢复结果。

该修复已包含在 0.4.3 发布包：`desktop/core/src/upstream/codex.rs` 的 Windows 启动参数显式覆盖 `sandbox_mode="workspace-write"`，保留原有 `agentdeck` 权限配置、审批及 MXC 设置，不修改用户文件。Windows 校验兼容空值和 workspace-write，仍拒绝 danger-full-access；macOS 与 Linux 的原有模式要求保持。权限模式、默认权限名称及继承关系分别报告具体字段，模式值只回显已知枚举，其他配置值不写入诊断。文件系统、网络、临时目录、MCP/hooks 和实际会话权限检查继续执行，未修改逐轮普通/完整访问切换逻辑。
